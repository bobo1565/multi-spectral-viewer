# 实时监控切换大图时黑屏问题分析与修复

## 现象

在实时监控页面，点击缩略图的"切换到大图"按钮或单击缩略图画面后：

- **偶发黑屏**：切换后目标窗口（大图或小图）渲染为全黑，无视频流画面
- **刷新流按钮无效**：点击"刷新流"无法恢复
- **切走再回来可恢复**：切换到其他页面（分析/摄像头管理）再切回实时监控，画面恢复正常

## 根因分析

### MJPEG 流的特性

实时监控使用 MJPEG（Motion JPEG）流传输，通过 HTTP `multipart/x-mixed-replace` 响应的方式，在单个长连接中持续推送视频帧。浏览器端通过 `<img>` 标签的 `src` 属性指向 MJPEG 流 URL，即可持续渲染。

MJPEG 连接的特点：

1. 连接建立后持续保持，直到 `<img>` 元素从 DOM 中移除或 `src` 被改变
2. 如果在短时间内关闭旧连接并重建同 URL 的新连接，浏览器可能出现连接状态混乱，导致新 `<img>` 元素无法正常加载流数据

### 第一版方案：两个独立容器（有问题）

原始代码将 5 个 tile 渲染在**两个不同的 DOM 父容器**中：

```tsx
<div className="live-stage">
    <div className="live-main-stage">
        {mainTile && renderTile(mainTile, 'main')}      {/* 1个大图 */}
    </div>
    <div className="live-thumbnail-row">
        {thumbnailTiles.map(renderTile)}                 {/* 4个小图 */}
    </div>
</div>
```

**切换流程**（以 Camera A（缩略图）↔ Camera B（大图）互为例）：

1. 用户点击 Camera A 的切换按钮 → `setMainId(A.id)`
2. React 重新渲染：
   - 旧结构：`main-stage` 包含 B 的 `<img>`，`thumbnail-row` 包含 A/C/D/E 的 `<img>`
   - 新结构：`main-stage` 包含 A 的 `<img>`，`thumbnail-row` 包含 B/C/D/E 的 `<img>`
3. React 的 key reconciliation **仅在同级 sibling 之间工作**。由于 `main-stage` 和 `thumbnail-row` 是不同的父容器：
   - B 的 `<img>` 在 `main-stage` 中**被卸载**（DOM 移除，MJPEG 连接关闭）
   - A 的 `<img>` 在 `thumbnail-row` 中**被卸载**（DOM 移除，MJPEG 连接关闭）
   - B 的新 `<img>` 在 `thumbnail-row` 中**被挂载**（新建 DOM，开启新 MJPEG 连接）
   - A 的新 `<img>` 在 `main-stage` 中**被挂载**（新建 DOM，开启新 MJPEG 连接）

4. 浏览器在极短时间内：
   - 关闭了 Camera A 的 MJPEG 连接（旧 `<img>` 被卸载）
   - 立即创建了新的 Camera A 的 MJPEG 连接（新 `<img>` 挂载，URL 可能相同）

5. 这种 **"快速关闭→立即重建同 URL 连接"** 的行为，在浏览器的连接管理中可能出现竞态条件，导致新的 MJPEG 流连接无法正常建立 → **黑屏**。

### 第二版尝试：stageKey 强制重建（核武器方案）

通过在 `live-stage` 上加 `key={stageKey}`，切换时递增 `stageKey`，强制 React 完全卸载并重建整个舞台 DOM。这确实能解决黑屏（等价于"切走再回来"），但副作用大：所有 5 路流全部中断重建，体验差。

## 最终解决方案：单容器 + React DOM 复用

### 核心思想

**让所有 tile 成为同一父容器的 siblings**。React 在同一个父容器内进行 key reconciliation 时，如果新旧 children 中有匹配的 key，会**复用已有 DOM 元素**而非卸载重建。`<img>` 元素从未离开 DOM，MJPEG 连接零中断。

### 实现细节

#### 1. TSX 结构变更（`LivePanel.tsx`）

**之前**（两个容器，DOM 元素无法跨界复用）：
```tsx
<div className="live-stage">
    <div className="live-main-stage">
        {mainTile && renderTile(mainTile, 'main')}
    </div>
    <div className="live-thumbnail-row">
        {thumbnailTiles.map(item => renderTile(item, 'thumb'))}
    </div>
</div>
```

**之后**（单一容器，DOM 元素可跨界复用）：
```tsx
<div className="live-stage">
    {mainTile && renderTile(mainTile, 'main')}
    {thumbnailTiles.map(item => renderTile(item, 'thumb'))}
</div>
```

#### 2. 统一码率（`LivePanel.tsx:42`）

```tsx
const STREAM_QUALITY = 75;    // 大图和小图使用相同的码率
```

之前大图 85、小图 60 的不同质量导致两处 URL 不同，即使元素被复用也会因 `src` 变化而触发重连。统一码率后，同一摄像头的 URL 完全一致。

#### 3. 统一 img key（`LivePanel.tsx:329`）

```tsx
// 之前：key 包含 variant，大小图 key 不同，React 无法复用
key={`${cam.id}-${variant}-${refreshKey}`}

// 之后：key 不含 variant，大小图 key 完全相同
key={`${cam.id}-${refreshKey}`}
```

#### 4. 切换不改变 refreshKey（`LivePanel.tsx:212-225`）

```tsx
const handleSwapToMain = useCallback((cam_id: string) => {
    setMainId(cam_id);    // 仅更新 mainId，不递增 refreshKey
}, []);
```

`refreshKey` 不变 → 所有 img key 不变 → URL 中的 `&r=` 参数不变 → React 识别到相同 key → **复用 DOM 元素**。

### 切换流程（修复后）

1. 用户点击 Camera A 的切换按钮 → `setMainId(A.id)`
2. React 重新渲染，`live-stage` 内的 children 排序变化：
   ```
   之前: [B(main), A(thumb), C(thumb), D(thumb), E(thumb)]
   之后: [A(main), B(thumb), C(thumb), D(thumb), E(thumb)]
   ```
3. React reconciliation：
   - key `A-id-123` 的 `<div>` 元素从第 2 位移至第 1 位 → **复用已有 DOM**
   - key `B-id-123` 的 `<div>` 元素从第 1 位移至第 2 位 → **复用已有 DOM**
   - key `C-id-123`、`D-id-123`、`E-id-123` 位置不变 → **复用已有 DOM**
4. 每个 tile 仅更新 CSS class（`live-tile-main` ↔ `live-tile-thumb`）及对应的 overlay（最大化按钮显隐等）
5. `<img>` 元素始终保持在 DOM 中 → **MJPEG 连接零中断**

### CSS Grid 布局（`LivePanel.css`）

去掉 `live-main-stage` 和 `live-thumbnail-row` 的中间容器后，用 CSS Grid 直接控制 tile 的位置和大小：

```css
.live-stage {
    display: grid;
    grid-template-columns: 1fr 280px;
    grid-template-rows: repeat(4, minmax(0, 1fr));
    gap: 12px;
}

.live-tile-main {
    grid-row: 1 / -1;    /* 跨满左列所有 4 行 */
    grid-column: 1;
}

.live-tile-thumb {
    grid-column: 2;       /* 固定在右列，自动按行排列 */
}
```

响应式断点：
- **≤900px**：grid 切换为 2 列流式布局，大图 `grid-column: 1 / -1` 占满整行，缩略图在下方 2×2 排列
- **≤640px**：单列堆叠

## 关键洞察

| 问题 | 原因 | 解决 |
|------|------|------|
| 切换后黑屏 | 两个父容器导致 React 卸载/重建 `<img>`，MJPEG 连接中断 | 单容器 + key 复用，`<img>` 始终在 DOM 中 |
| 刷新流按钮无效 | `resumeStreamRendering` 仅递增 `refreshKey`，不解决连接竞态 | 同上，根本不需要重建连接 |
| 切走再回来能恢复 | 组件完全卸载再挂载，所有连接全新建立 | 同上的原理等价，但不需整个组件销毁 |
